# API фронтенда «Пожарный КП»

Полный машиночитаемый контракт находится в `api-contracts.json` (OpenAPI 3.0.3).

## Общие правила

- Базовый URL задаётся переменной `VITE_API_BASE_URL`, значение по умолчанию: `/api`.
- Формат запросов и ответов: `application/json`.
- Идентификаторы передаются как строки.
- Денежные значения передаются числами в рублях без форматирования.
- Проценты передаются числами, например `22`, а не `0.22`.
- Ошибка API должна иметь минимум поле `{ "message": "..." }`.
- После мутаций заявки сервер возвращает полную актуальную `OrderDetail`.
- Даты в прототипе отображаются строками. Для реального API рекомендуется ISO 8601.
- Авторизация в контракте описана как Bearer JWT. MSW её не проверяет.

## Роли

| Роль | Доступ |
| --- | --- |
| `manager` | Заявки, файлы, ручные параметры, просмотр справочников и КП |
| `admin` | Возможности менеджера, поставщики, товары, сертификаты, настройки и подтверждения |
| `sysadmin` | Полный доступ, управление ролями и правами |

Прямой запрос к запрещённой операции должен возвращать `403`.

### Заявки

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/orders?status=&search=` | Список и фильтрация заявок |
| `POST` | `/orders` | Создание заявки-черновика |
| `GET` | `/orders/{orderId}` | Полная карточка заявки |
| `POST` | `/orders/{orderId}/send` | Отправка на обработку |
| `POST` | `/orders/{orderId}/cancel-send` | Отмена отправки до начала обработки |
| `POST` | `/orders/{orderId}/close` | Закрытие с фиксацией итогового КП |
| `POST` | `/orders/{orderId}/archive` | Перемещение в архив |
| `POST` | `/orders/{orderId}/complete-check` | Завершение проверки ТХ |
| `POST` | `/orders/{orderId}/confirm-quote` | Подтверждение КП |
| `PATCH` | `/orders/{orderId}/quote` | НДС, скидка, поставщик и причина изменения |
| `POST` | `/orders/{orderId}/files` | Добавление файла в заявку |
| `GET` | `/orders/{orderId}/lines/{lineId}/offers` | Предложения прайсов по строке заявки (поиск по имени позиции) |
| `POST` | `/orders/{orderId}/quote` | Сборка КП по выбранным позициям (selections) |

`PATCH /orders/{orderId}/quote`: при ручном изменении `vatRate` или
`specialDiscount` поле `reason` обязательно. Изменение должно попадать в журнал
аудита и, при необходимости, создавать уведомление Администратору.

Ручные значения и подтверждение параметров ТХ правятся не через `/orders`, а
каноническими ручками Фазы 3: `POST /check-items/{itemId}/parameters`
(ручной параметр), `POST /parameters/{parameterId}/revisions` (правка значения
с `expectedVersion`/`reasonCode`/`comment`), `POST /check-items/{itemId}/parameters/confirm`
(подтверждение параметров позиции).

В промышленном API загрузку файлов лучше принимать как `multipart/form-data`.
Текущая MSW-реализация принимает `{ fileName, kind }`, чтобы не хранить бинарные
данные в прототипе.

## Статусы

### Заявка

- `draft` — черновик.
- `active` — в работе.
- `confirmation` — на подтверждении.
- `closed` — закрыта, только чтение.
- `archived` — архив, только чтение.

### Результат проверки

- `success` — соответствует/подтверждено.
- `warning` — требует проверки.
- `danger` — не соответствует.
- `missing` — значение не найдено.
